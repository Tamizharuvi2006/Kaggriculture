## Contradictory Evidence

`APEX4_RELEASE_MANIFEST.json` claims:

- Gate 1: 67.4% over 92 matches, passed
- Gate 2: 72.5% over 200 scenarios, passed
- Gate 3: 71.0% over 100 unseen matches, passed
- Overall verdict: `RELEASE_READY`

However, `reports/APEX4_RELEASE_DECISION.md` and `reports/APEX4_GATE_REPORT.json` record:

- Gate 1: 50.0% over 92 matches, failed
- Gates 2-4: skipped
- Overall verdict: `FALSIFIED_GATE_1` / `REJECTED_FOR_PRODUCTION`

These records cannot both describe the same release candidate and evaluation contract. The 70.5% controlled/pre-launch figure therefore cannot be treated as a verified release gate until provenance is reconciled.

## Required Resolution Before Upload

1. Identify which gate run produced each result and its exact candidate hash.
2. Confirm whether the 67.4%/72.5%/71.0% records are newer, valid, and generated by the same entrypoint.
3. Reconcile the conflicting release decision and manifest, preserving both records.
4. Re-run only the minimum read-only packaging/hash/parity checks after reconciliation.
5. Obtain explicit human approval before any live submission.

Until then, APEX 3.5 remains the only verified live baseline and the rollback copy is ready.
